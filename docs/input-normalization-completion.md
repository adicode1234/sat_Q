## 2. Existing restrictions discovered

Pair dimensions/CRS/transforms/band order were globally required to match. PNG/JPEG required benchmark provenance. Multi-date capped at eight. The gateway capped files at 32 MiB and the proxy capped entire requests at 64 MiB. Query limits were duplicated at 2000 characters. Services reopened original files. Physical area trusted the presence of CRS/transform without a metadata-quality capability check. Unknown SAR units already disabled calibrated evidence, but single-image SAR responses gave only an unavailable-calibration message.

The workspace has no `.git` directory. `git status` and `git diff` were attempted and could not inspect contributor changes. Existing source files were backed up to `.repair-backup/input-normalization-before`; edits were limited to the affected paths. Benchmark artifact hashes were captured before editing.

## 3. Hard failures converted to preprocessing

Safe dimension, valid CRS, affine/resolution, known band-order and common-band differences normalize automatically. Temporal normalization uses the first observation. Fusion uses optical as the reference, retaining input IDs. Nonshared cells are masked on all observations; fusion crops to the shared window. Visual translation requires reliable, bounded diagnostics and verified residual alignment.

## 4. Restrictions converted to warnings or limited capabilities

Ordinary RGB files use visual-only mode. Missing/placeholder geography disables physical area and coordinates. Unknown SAR calibration permits relative summaries/proxy analysis with calibrated claims disabled. Missing requested index bands produce a targeted unavailable measurement, without rejecting unrelated visual tasks. Extra temporal bands are excluded transparently. Missing bitemporal acquisition dates use declared before/after slots with a warning, without inventing dates.

## 5. Restrictions preserved

Exactly two bitemporal observations; compatible temporal modalities; exactly one optical and one SAR for fusion; meaningful overlap; ordered real dates for multi-date trends; known required spectral identities; trustworthy geography for real area; known units for calibrated SAR claims; LOW_TRUST/refusal and independent evidence separation. Corrupt or malformed imagery, unrelated images and unstable registration remain incompatible. No invented geolocation, sensor metadata, calibration, probabilities or Cartosat/RISAT validation.

## 6. Configuration limits

Defaults: `SATQUERY_MAX_UPLOADS=20`, `SATQUERY_MAX_UPLOAD_MB=128`, `SATQUERY_MAX_QUERY_CHARS=8000`, `SATQUERY_MAX_MULTIDATE=20`. Multi-date max cannot exceed upload max. `SATQUERY_MAX_DECODED_MB=1024` bounds decoded/reference-grid memory. Existing 16-million-pixel and 16-band per-image limits remain. Reprojection, resampling, band reorder and visual registration have explicit environment switches. Nginx permits 2600 MiB aggregate requests; gateway enforces file/count limits.

## 7. Preprocessing architecture

Upload → content inspection → modality/task validation → safe normalization → common-grid/overlap verification → ready status → execution. Canonical image dictionaries carry original metadata, source/working paths internally, flags, capabilities, SAR unit status, warnings and preprocessing steps. Execution persists float32/NaN derivatives under job-specific normalized directories, preserving source tags/descriptions and provenance. The writer rereads and compares every band, grid, dimensions and descriptions. Originals are hash-verified unchanged in tests.

## 8. API/schema changes

Existing endpoints retained. Added `GET /api/config`; `/api/inspect` accepts optional `query`. Additive validation fields include `issues_detected`, `actions_taken`, `preprocessing_steps`, `warnings`, `blocking_errors`, `capabilities`, `unavailable_tasks`, and `has_limitations`. Four readiness states are supported. Successful preprocessing takes status precedence when warnings coexist; capability flags remain authoritative. Structured errors include file/query/count limits, no overlap, modality mismatch, preprocessing failure and memory-budget violations.

## 9. Frontend changes

Inspector displays automatic fixes, warnings, overlap and original/normalized dimensions. Visual-only and uncalibrated SAR restrictions are explicit. Upload/query limits come from the gateway. Default SAR units are UNKNOWN, avoiding an implicit dB assumption. Input quality, model confidence, evidence support, consensus and final trust remain distinct. Stale inspection responses are discarded after inputs or queries change.

## 16. Remaining genuine limitations

- Browser automation is unavailable in this session; there is no claimed visual UI review or screenshot proof.
- Visual registration is translation-only with conservative resize/shift limits. Cross-sensor alignment without valid geospatial grids is rejected.
- Numeric spectral aliases need sensor context; ambiguous band identities are not guessed.
- Temporal SAR observations with different unit states still require consistent units; raw db/linear/unknown values are not silently compared.
- Existing specialists use bounded in-memory arrays. Large decoded jobs can still be rejected even if compressed upload sizes fit.
- Successful originals and normalized derivatives follow the existing retained-upload lifecycle; the project has no automatic successful-job expiration policy.
- Plausible georeferencing is not a survey-accuracy certificate. Heuristic metadata checks cannot authenticate metadata or detect every forged transform.
- Actual original river files remain unavailable. Benchmark performance was deliberately not re-evaluated.
